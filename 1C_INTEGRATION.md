# Инструкция по интеграции 1С с сервисом синхронизации остатков

Данный сервис предназначен для автоматической и автономной передачи складских остатков из учетной системы 1С на маркетплейсы Wildberries и Ozon. 

Задача 1С-специалиста — настроить стандартную обработку или регламентное задание выгрузки актуального среза свободных остатков по расписанию (рекомендуемый интервал: каждые 10–15 минут).

---

## 📊 1. Требования к структуре и формату файла выгрузки

Сервис производит высокоскоростной потоковый парсинг данных, поэтому файл должен строго соответствовать следующим техническим параметрам:

1. **Имя файла:** `stocks.csv` (строго в нижнем регистре).
2. **Кодировка:** `UTF-8` (без BOM).
3. **Формат данных:** Стандартный CSV (разделитель колонок — запятая `,`).
4. **Заголовки (первая строка файла):** Файл должен содержать ровно две обязательные колонки с точным совпадением имен:
   * `item_sku` — внутренний артикул/SKU товара (строковое значение, пробелы по краям автоматически обрезаются сервисом). Должен соответствовать полю `sku_internal` в репозитории маппинга.
   * `quantity` — количество доступного для продажи товара на складе (целое неотрицательное число). Если остаток отрицательный, строка будет отфильтрована как некорректная.

### Пример корректного содержимого файла `stocks.csv`:
```csv
item_sku,quantity
SKU-1001,12
SKU-1002,0
SKU-1003,45
SKU-2001,30
```

## ⚙️ 2. Варианты интеграции (в зависимости от выбранной сборки)

Настройте выгрузку из 1С в соответствии с тем, какой пакет архитектуры развернут в вашей компании:

### Вариант А. Сборка повышенной надежности (`production_docker_ftp`)
Применяется, если сервис развернут на удаленном сервере (в облаке) или выделенном сервере в локальной сети. В стек встроен изолированный FTP-приемник на базе Alpine Linux. 
1С должна отправлять сформированный файл по сетевому протоколу FTP.

* **Адрес хоста (IP):** `IP-адрес вашего сервера` (или `127.0.0.1` при локальном тестировании)
* **Порт подключения:** `21`
* **Логин:** `ftp_1c_user`
* **Пароль:** `secret_ftp_pass_2026` *(значения логина/пароля могут быть изменены в файле .env)*
* **Режим соединения:** Строго **Пассивный режим (PASV)** — критично для стабильного прохождения трафика через Docker-сеть.
* **Каталог на сервере:** Файл `stocks.csv` необходимо выгружать прямо в корневую директорию FTP-пользователя.

### Вариант Б. Ультралегкая сборка (`production_windows_light`)
Применяется, если сервис запущен локально на том же самом Windows-компьютере, где работает 1С (или в общей доступной папке сетевого диска офиса).
* 1С должна перезаписывать сформированный файл `stocks.csv` локально, сохраняя его напрямую в корневую директорию папки со скриптом.

## 🛡️ 3. Встроенные защитные механизмы сервиса

Вам не нужно настраивать в 1С сложные проверки доступности или блокировки файлов. В сервис уже заложены следующие защитные шлюзы:
* **Exponential Backoff Shield:** Если маркетплейсы временно недоступны или отвечают ошибками, робот не падает, а уходит в спящий режим рантайма, отправляет алерт в Telegram и повторяет попытку в следующий запланированный тик планировщика.
* **File Locking Protection:** Скрипт оснащен автоматическим модулем контроля стабильности файлов. Перед чтением он проверяет, не изменяется ли размер `stocks.csv`. Если 1С в данный момент занята долгой записью тяжелого файла, робот безопасно подождет окончания транзакции и не начнет парсинг недозаписанных данных.
